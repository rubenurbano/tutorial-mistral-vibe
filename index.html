Cómo leer y aprovechar este tutorial

Este documento está escrito para alguien que nunca ha usado una terminal ni ha programado. Cada capítulo explica un concepto siguiendo la secuencia pedagógica (QUÉ ES → PARA QUÉ SIRVE → POR QUÉ IMPORTA → CÓMO SE HACE → EJEMPLO → PRÁCTICA → ERRORES → RESUMEN), te hace practicarlo y te da una forma de comprobar que lo has hecho bien. Si te saltas una comprobación, es probable que algo falle más adelante sin que sepas por qué.

Cómo se distinguen los comandos

Hay dos lugares distintos donde escribirás cosas, y no hay que mezclarlos:

  1. En PowerShell: la ventana de Windows donde escribes órdenes al sistema. Los bloques de código de este tipo llevan el encabezado «En PowerShell».
  2. Dentro de Vibe: la pantalla de MISTRAL VIBE una vez arrancado. Allí escribes peticiones en español o comandos que empiezan por /. Estos bloques llevan el encabezado «Dentro de Vibe».

Regla de oro: No escribas nunca los símbolos PS> ni > que puedan aparecer en ejemplos de pantalla: son el indicador del propio programa, no forman parte de lo que tecleas.

Cuando una funcionalidad no es estable o no se ha podido comprobar directamente, se indica con estas etiquetas:

PARTE I. COMPRENDER MISTRAL VIBE

Capítulo 1. ¿Qué es MISTRAL VIBE?

1.1. Qué es

MISTRAL VIBE es un programa de código abierto (licencia Apache-2.0) creado por la empresa francesa Mistral AI. El repositorio oficial lo describe como un asistente de programación para la línea de comandos que funciona con los modelos de Mistral. Le escribes en lenguaje natural, por ejemplo «busca todos los TODO de este proyecto», y él explora tus carpetas, lee archivos, los modifica y ejecuta comandos para cumplir lo que pides. OFICIAL

El programa se arranca escribiendo la palabra vibe en una terminal. A veces verás escrito «Vibe», «Mistral Vibe» o «Vibe CLI». Todos se refieren a lo mismo en este tutorial. Ojo: Mistral usa también el nombre «Vibe» para otros productos (una aplicación web y móvil, una extensión para VS Code y sesiones web llamadas Vibe Code Web). Este tutorial trata solo de la versión de línea de comandos, la CLI.

1.2. Para qué sirve

Sirve para tareas en las que hay archivos de por medio, sobre todo de código, pero no solo:

  • Entender un proyecto que no escribiste tú.
  • Crear páginas web, pequeñas aplicaciones y scripts.
  • Corregir errores y mejorar código existente.
  • Buscar y reorganizar información dentro de muchos archivos.
  • Automatizar tareas repetitivas con programas pequeños.

1.3. Qué problemas resuelve y por qué importa

Programar exige conocer la sintaxis de un lenguaje, las herramientas y los detalles de cada sistema. Un agente como Vibe te quita buena parte de esa barrera: tú describes el resultado y él escribe el código, lo guarda donde corresponde y puede ejecutarlo. No elimina la necesidad de revisar lo que hace. Quien no revisa, acepta a ciegas, y esa es la mayor fuente de problemas con estas herramientas.

1.4. Cómo funciona, en pocas palabras

  1. Tú escribes una petición.
  2. Vibe envía tu petición, junto con información de tu proyecto (estructura de carpetas, estado de Git), a un modelo de lenguaje a través de internet.
  3. El modelo responde con texto o con una petición de usar una herramienta, por ejemplo «lee este archivo» o «ejecuta este comando».
  4. Vibe ejecuta la herramienta, pidiéndote permiso si corresponde, y devuelve el resultado al modelo.
  5. El ciclo se repite hasta que el modelo considera que ha terminado.

1.5. Qué significa «agente de programación»

Un agente no solo conversa: actúa. Puede decidir qué pasos dar, usar herramientas y comprobar el resultado de sus propias acciones. El README oficial lo describe como una interfaz conversacional con tu código, que descompone tareas complejas y usa herramientas para leer, escribir y buscar archivos, gestionar una lista de tareas y ejecutar comandos.

1.7. Qué puede hacer y qué no

Puede, según la documentación oficial:

  • Leer, crear y modificar archivos (read_file, write_file, edit).
  • Buscar texto con grep.
  • Ejecutar comandos de shell.
  • Llevar una lista de tareas (todo).
  • Hacerte preguntas cuando le falta información (ask_user_question).
  • Delegar trabajo en subagentes (task).
  • Recuperar páginas y hacer búsquedas web (web_fetch, web_search, disponibles desde la versión 2.3.0 según el CHANGELOG).
  • Conectarse a servidores MCP y cargar Skills (capítulo 20).

No puede, o no debes esperar que lo haga:

  • Garantizar que su código sea correcto. Hay que probarlo siempre.
  • Conocer tus intenciones si no las explicas con precisión.
  • Trabajar sin conexión con modelos de Mistral (existe una vía documentada para modelos locales que queda fuera del flujo estándar).
  • Protegerte de ti mismo: si le das permiso para todo, hará todo lo que decida el modelo.

1.8. Ejemplos del mundo real

  • Una persona que gestiona un pequeño negocio pide una hoja HTML que calcule precios con descuento y la abre en el navegador.
  • Un estudiante pide que se renombren cientos de fotos con un patrón fijo.
  • Alguien hereda una carpeta con un proyecto antiguo y pide un resumen de qué hace cada archivo.

Capítulo 2. Conocimientos mínimos necesarios

Aquí tienes las definiciones imprescindibles. No hace falta memorizarlas: las verás aplicadas una y otra vez.

2.1. Terminal, consola y línea de comandos

  • Terminal: la ventana donde escribes órdenes en forma de texto en lugar de hacer clic.
  • Consola: en la práctica, lo mismo. Históricamente era el nombre de la pantalla y el teclado conectados a un ordenador. Hoy se usan como sinónimos.
  • Línea de comandos: la línea donde escribes la orden y pulsas Enter.
  • Shell o intérprete: el programa que lee lo que escribes y lo ejecuta. PowerShell es un shell. CMD (Símbolo del sistema) es otro, más antiguo.

Diferencia importante: la terminal es la ventana, el shell es el programa que hay dentro. En Windows 11 puedes abrir PowerShell dentro de Windows Terminal o en su propia ventana azul.

2.2. PowerShell y CMD

Los dos vienen con Windows, pero no hablan igual. PowerShell es más moderno y es el que usaremos. Una orden como Get-ChildItem funciona en PowerShell y no en CMD. Cuando un tutorial de internet te dé un comando, comprueba para cuál de los dos está escrito.

2.3. Python

Python es un lenguaje de programación. Vibe está escrito en Python, por lo que necesita un intérprete de Python (3.12 o superior según la documentación) para ejecutarse. Vibe no es Python: es un programa hecho con Python. Como veremos, la herramienta uv puede descargar Python por ti si hace falta.

2.4. Modelo de lenguaje, agente y API

  • Modelo de lenguaje: el «cerebro» que genera texto (Mistral Medium, Mistral Large, Codestral). Vive en los servidores de Mistral.
  • Agente: en Vibe, un perfil de configuración que decide qué acciones se aprueban automáticamente (ask, plan, accept-edits, auto-approve...).
  • API: un canal por el que un programa pide cosas a otro por internet. Vibe usa la API de Mistral.
  • API Key (clave de API): una contraseña larga que identifica tu cuenta ante la API. Quien la tenga puede gastar tu cuota. Hay que tratarla como una contraseña bancaria.

2.5. Directorio de trabajo, archivo y repositorio

  • Archivo: un documento con nombre, como notas.txt.
  • Directorio o carpeta: un contenedor de archivos y otras carpetas.
  • Directorio de trabajo: la carpeta en la que está «situada» la terminal. Vibe trabaja sobre la carpeta desde la que lo arrancas. Es la decisión de seguridad más importante del tutorial.
  • Repositorio: una carpeta de proyecto bajo control de versiones con Git (sistema que guarda el historial de cambios). No todo proyecto es un repositorio.

2.6. Qué significa ejecutar código o un comando

Ejecutar es pedir al ordenador que realice las instrucciones escritas. Cuando Vibe ejecuta un comando por ti, lo hace con los mismos permisos que tu usuario de Windows. Por eso el sistema de aprobaciones existe.

2.7. Instalación y configuración

Instalar es copiar el programa en tu ordenador. Configurar es decirle cómo comportarse y con qué cuenta trabajar. Se puede estar instalado y sin configurar (Vibe arrancará, pero te pedirá iniciar sesión).

Ejercicio de comprensión del Capítulo 2 (Haz clic para ver solución)

Pregunta: ¿Cuál es la diferencia entre PowerShell y Vibe? ¿Dónde escribirías vibe?

Solución: PowerShell es un shell de Windows donde escribes comandos del sistema. Vibe es un programa que se arranca desde PowerShell escribiendo vibe y que a partir de ese momento tiene su propia pantalla.

Capítulo 3. Cómo trabaja MISTRAL VIBE

3.1. Esquema visual del ciclo de ejecución

DIAGRAMA DE FLUJO DEL AGENTE
[1. Tú escribes una petición] │ ▼ [2. Vibe añade contexto del proyecto (carpetas, Git, AGENTS.md)] │ ▼ [3. Modelo de lenguaje en los servidores de Mistral] │ ├─► ¿No pide herramienta? ──► [Respuesta final en pantalla] │ └─► ¿Pide usar herramienta? ──► [Sistema de permisos] ├─► Aprobada ──► [Vibe ejecuta en tu PC] ──► (Vuelve al modelo) └─► Denegada ──► [El modelo recibe negativa] ──► (Vuelve al modelo)

3.2. Piezas que intervienen

  • Interacción con el usuario: interfaz de texto moderna dentro de la terminal, con autocompletado de comandos / y de rutas con @, historial persistente y temas visuales.
  • Comunicación con los modelos: por defecto con los modelos de Mistral por API. El modelo integrado es Mistral Medium 3.5 (alias mistral-medium-3.5). También puedes configurar otros proveedores compatibles, como OpenRouter, mediante config.toml.
  • Lectura y escritura de archivos: read_file, write_file (solo crea archivos nuevos y se niega a sobrescribir uno existente desde CHANGELOG 2.14.0) y edit (modifica uno existente).
  • Ejecución de comandos: herramienta de shell (variante basada en Git Bash o en PowerShell en Windows).
  • Gestión de tareas: la herramienta todo mantiene una lista de lo que el agente va haciendo. Se muestra u oculta con Ctrl+T.
  • Agentes incorporados: ask, plan, accept-edits, auto-approve, además de smart-approve y lean con condiciones.
  • Subagentes: el agente principal puede delegar tareas a otros agentes con la herramienta task. Existe uno incorporado llamado explore.
  • Contexto del proyecto: estructura de carpetas, estado de Git y archivos AGENTS.md.
  • Sistema de permisos: combina el agente activo, las carpetas de confianza y los permisos por herramienta.

3.3. Flujo de trabajo recomendado

  1. Abres PowerShell en la carpeta del proyecto.
  2. Arrancas vibe.
  3. Pides un análisis con el agente plan o ask.
  4. Revisas el plan propuesto.
  5. Cambias a accept-edits para ejecutarlo.
  6. Revisas los cambios y los pruebas tú mismo.
  7. Si todo es correcto, guardas una copia o un commit; si no, explicas el fallo y repites.
Ejercicio de comprensión del Capítulo 3 (Haz clic para ver solución)

Pregunta: ¿Por qué Vibe necesita internet para funcionar con modelos de Mistral y en qué momento exacto puede modificar tus archivos?

Solución: Vibe envía contexto y petición al modelo por internet; los archivos solo se modifican cuando el modelo pide una herramienta de escritura (write_file o edit) y el sistema de permisos la autoriza.

Capítulo 10. Primer contacto práctico

Dentro de $HOME\Documents\vibe-lab, practica las acciones esenciales:

  • Salto de línea sin enviar: pulsa Ctrl+J (o Shift+Enter en terminales compatibles).

NIVEL 1 PRINCIPIANTE (Preguntas 1 a 11)

Pregunta 1. ¿Qué es MISTRAL VIBE?

Es un asistente de programación de código abierto de Mistral AI que se maneja desde la línea de comandos. Le escribes peticiones en español, él las envía a un modelo de lenguaje y, con tu permiso, lee, crea y modifica archivos y ejecuta comandos en la carpeta donde lo arrancaste. Pregunta 2. ¿Necesito saber programar para usarlo?

Pregunta 3. ¿Cuál es la diferencia entre PowerShell y CMD?

Ambos son intérpretes de comandos de Windows. PowerShell es más moderno y tiene órdenes como Get-ChildItem. CMD es el antiguo Símbolo del sistema. Este tutorial usa PowerShell. Se distinguen porque el indicador de PowerShell empieza por PS.

Pregunta 4. ¿Tengo que instalar Python?

No necesariamente. La documentación de Mistral dice que Python 3.12 o superior hace falta para una instalación manual (con pip) y que uv lo descarga si es necesario. Con el método recomendado (uv) puedes no instalarlo tú. Aun así, saber instalarlo y comprobarlo ayuda a resolver problemas.

Pregunta 5. ¿Qué es uv y por qué se usa?

Es un gestor de herramientas de Python hecho por Astral. Instala Vibe en un entorno propio, aislado de otros programas, y coloca el comando vibe en tu PATH. También permite actualizarlo (uv tool upgrade mistral-vibe) y desinstalarlo.

Pregunta 6. ¿Qué comandos instalan Vibe en Windows 11?

Dos, en PowerShell y por separado. Primero uv: powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex". Luego, en una ventana nueva, uv tool install mistral-vibe. Comprueba con vibe --version. El README advierte que Windows funciona pero el soporte oficial se orienta a sistemas UNIX.

Pregunta 7. Escribo vibe y Windows dice que no lo reconoce. ¿Qué hago?

Lo más probable es que la ventana sea anterior a la instalación y no conozca el PATH nuevo. Cierra PowerShell y abre otra. Si sigue fallando, ejecuta uv tool update-shell, abre una ventana nueva y repite vibe --version. Comprueba también que uv tool list muestra mistral-vibe.

Pregunta 8. ¿Necesito una clave de API?

No siempre. Al primer arranque puedes iniciar sesión con tu cuenta de Mistral en el navegador y Vibe gestiona las credenciales. La clave de API es otra vía, útil para otros proveedores, automatización o resolver problemas. Si usas clave, no la compartas nunca en chats, capturas ni repositorios. vibe --setup repite el asistente.

Pregunta 9. ¿En qué carpeta debo arrancar Vibe?

En una carpeta específica del proyecto, como Documents\vibe-lab. Nunca en tu carpeta de usuario completa. Vibe trabaja sobre la carpeta actual y puede leer y modificar sus archivos, así que conviene limitar el alcance.

Pregunta 10. ¿Cómo salgo de Vibe?

Escribe /exit, o exit, quit, :q. También puedes pulsar Ctrl+C o Ctrl+D dos veces seguidas en aproximadamente un segundo. Escape no sale: interrumpe la respuesta en curso.

Pregunta 11. ¿Es gratis?

Vibe en sí es gratuito y de código abierto (Apache-2.0), pero usa modelos alojados que consumen cuota. La documentación de Mistral indica que los planes Free y Pro de Mistral incluyen Vibe Code con límites de uso, y que puede activarse el pago por uso, desactivado por defecto. Los planes cambian: consulta la web de Mistral.

NIVEL 2 INTERMEDIO (Preguntas 12 a 22)

Pregunta 12. ¿Qué diferencia hay entre los agentes ask, plan, accept-edits y auto-approve?

Cambian lo que se aprueba solo. ask pide permiso para todo. plan es de solo lectura. accept-edits aprueba las ediciones de archivos y sigue preguntando por los comandos de shell. auto-approve lo aprueba todo, incluidos los comandos, y solo es razonable en entornos desechables. Cambias con Shift+Tab o vibe --agent NOMBRE.

Pregunta 13. ¿Cuál es el agente por defecto y cómo lo cambio?

Según el README y la documentación de Mistral, accept-edits. Se cambia con default_agent = "ask" en config.toml, o con /config. La opción --agent en la línea de comandos manda sobre la configuración para esa ejecución.

Pregunta 14. ¿Cómo hago que Vibe lea un archivo concreto?

Escribe @ seguido del nombre y elige el archivo del autocompletado: «Resume @notas.txt». Esa mención se convierte en una lectura con read_file. Con imágenes (.png, .jpg, .jpeg, .gif, .webp) y un modelo con visión, se envían como contenido multimodal.

Pregunta 15. ¿Qué diferencia hay entre write_file y edit?

write_file crea archivos nuevos y se niega a sobrescribir los existentes. edit modifica una parte de un archivo existente y muestra un diff. Si pides que «rehaga» un archivo existente, Vibe usará edit.

Pregunta 16. ¿Cómo escribo una buena petición?

Con cinco elementos: objetivo, contexto, límites, resultado esperado y comprobación. «Haz una web» es vaga; «crea un único index.html para una panadería con tres secciones y sin librerías externas, y dime cómo abrirlo» es concreta. Pide planes primero y divide tareas grandes.

Pregunta 17. ¿Qué hace el ! delante de un texto?

Ejecuta ese comando directamente en tu shell, sin pasar por el modelo: !dir. Qué shell se usa exactamente en Windows depende de la configuración y de las herramientas disponibles, así que si un comando falla, prueba su equivalente.

Pregunta 18. ¿Qué hace /compact?

Resume el contexto de la conversación para liberar espacio, conservando la sesión y lo visible. Acepta instrucciones adicionales después del comando. Es útil cuando la conversación es larga y notas que Vibe olvida detalles.

Pregunta 19. ¿Cómo retomo una conversación anterior?

Con vibe --continue retomas la última de la carpeta actual. Con vibe --resume abres un selector, o /resume dentro de Vibe. La sesión conserva el modelo con el que empezó. El registro de sesiones debe estar activado.

Pregunta 20. ¿Dónde está config.toml y cuál manda?

En $HOME\.vibe\config.toml (usuario) y en .vibe\config.toml (proyecto, solo si confías en la carpeta). El del proyecto prevalece sobre el de usuario. El archivo no existe hasta que guardas un ajuste. Si falla tras editarlo, renómbralo y arranca de nuevo.

Pregunta 21. ¿Cómo cambio de modelo?

Con /model dentro de Vibe, o con active_model en config.toml. /model solo lista los modelos que tienes configurados. El modelo integrado es Mistral Medium 3.5; los demás se añaden con bloques [[models]].

Pregunta 22. ¿Qué es la confianza de carpeta y qué es AGENTS.md?

Un proyecto puede traer .vibe/, AGENTS.md o .agents/skills/ que alteran el comportamiento de Vibe. Vibe solo los carga si confías en la carpeta. AGENTS.md contiene tus instrucciones permanentes. Revisa estos archivos antes de confiar en un proyecto ajeno.

NIVEL 3 AVANZADO (Preguntas 23 a 33)

Pregunta 23. ¿Cómo funcionan las aprobaciones en modo programático?

En vibe --prompt, nadie puede responder a un permiso, así que Vibe rechaza cada llamada que lo necesitaría, salvo que pases --auto-approve o --yolo. Con el agente por defecto, las ediciones pasan y los comandos de shell no. Diseña automatizaciones que solo lean y escriban, o ejecútalas en un entorno aislado.

Pregunta 24. ¿Cómo limito el coste de una ejecución automática?

Con --max-price (dólares), --max-turns y --max-tokens. Si se supera el límite, la sesión se interrumpe y el resultado puede quedar incompleto. En una sesión interactiva, /status muestra el uso.

Pregunta 25. ¿Cómo añado un servidor MCP y qué riesgo tiene?

Con vibe mcp add NOMBRE --url ... o con bloques [[mcp_servers]] en config.toml. Si no das clave, usa OAuth y abre el navegador. Cada herramienta aparece como {servidor}_{herramienta}. Riesgo: actúa sobre servicios externos. Mantén permission = "ask" y usa solo servidores de confianza.

Pregunta 26. ¿Qué es una Skill y cómo se crea?

Una carpeta con un SKILL.md que tiene un encabezado (nombre, descripción, user-invocable, allowed-tools) y el cuerpo con las instrucciones. La colocas en ~/.vibe/skills/ o en .vibe/skills/ de un proyecto de confianza. Con user-invocable: true aparece como comando de barra.

Pregunta 27. ¿Cuándo conviene delegar en subagentes?

Cuando la tarea es de exploración o lectura que ensucia el contexto del agente principal, como analizar una carpeta grande. La herramienta task los invoca; explore es el incorporado, de solo lectura. Heredan los permisos de la sesión y los hooks, así que ten cuidado con lo que autorizas.

Pregunta 28. ¿Qué son los hooks y cuándo usarlos?

Comandos que Vibe ejecuta en puntos del ciclo: post_agent, pre_tool y post_tool. Un pre_tool puede denegar una llamada o reescribir sus argumentos. Sirven para políticas de seguridad o auditoría. En Windows, el comando se ejecuta sin shell, así que debe ser un ejecutable. Es un tema avanzado.

Pregunta 29. ¿Qué diferencia real hay entre smart-approve y auto-approve?

smart-approve clasifica cada llamada con un modelo: ejecuta las seguras y te consulta en las arriesgadas. Aun así, la documentación avisa de que no es una sandbox. auto-approve no consulta nada. Ambos pueden ejecutar acciones con los permisos de tu usuario. Para código no fiable, usa ask o un entorno aislado.

Pregunta 30. ¿Qué es la inyección de instrucciones y cómo me afecta?

Un archivo, una web o una respuesta de un servidor MCP puede contener texto que intenta ordenar al modelo cosas que tú no pediste, como filtrar un archivo. Se reduce con agentes que pidan aprobación, permisos mínimos, outside_workdir = "deny", y no usando auto-approve con contenido ajeno.

Pregunta 31. ¿Cómo personalizo Vibe a fondo?

Con config.toml (agente por defecto, modelos, permisos por herramienta, filtros), agentes en ~/.vibe/agents/, prompts de sistema y de compactación en ~/.vibe/prompts/, Skills, AGENTS.md, hooks y la variable VIBE_HOME, que cambia la carpeta raíz. vibe config schema ayuda a validar la configuración.

Pregunta 32. ¿Qué shell usa Vibe en Windows y es necesario WSL2?

No hay una respuesta única: según el README, una prueba A/B decide entre la herramienta bash clásica y variantes gestionadas (git_bash si hay Git Bash; si no, powershell). No es necesario WSL2 para empezar, aunque bajo WSL Vibe se ejecuta como Linux, el entorno que Mistral soporta oficialmente. Instalar Git para Windows amplía opciones.

Pregunta 33. ¿Cómo sería un flujo de trabajo profesional?

Commit previo; plan con plan; revisión del plan; ejecución en pasos con accept-edits; prueba tuya de cada paso; commit; revisión crítica final con un agente de solo lectura. Con AGENTS.md para reglas, Skills para tareas repetidas, límites en modo programático y copias de seguridad.
